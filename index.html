API SDKs

Server-side clients for the IronDome disposable-email detection API. Keep your account key on your server and reuse one client.

  • JavaScript / TypeScript: Node.js, Fetch, and Deno.
    npm install @irondome-dev/sdk@0.2.0
  • Go 1.23+
    go get github.com/IrondomeDev/sdks/go@v0.2.0
  • Rust
    cargo add irondome-sdk@0.2.0
  • Python 3.11+: install from source. PyPI publication is pending; follow the package’s current instructions.

Mail Canon

Normalize email addresses and derive provider-aware matching keys locally. No API calls, DNS queries, or mailbox lookups.

Available in JavaScript, Python, Rust, Go, Java, PHP, and C#. Package releases are independent; check the guide for your language and installed version.

  • Package guides
  • Behavior contract
  • Published releases

Canonical equality is not proof of identity. Do not use it alone to authorize login, recovery, account linking, or account merging. Preserve the submitted address and verify mailbox ownership.

Run a signup example

A small Node.js server-side screening integration with mock account creation and verification delivery. The offline demo and tests need Node.js 22+, but no API key, live requests, or real accounts.

git clone https://github.com/IrondomeDev/irondomedev.github.io.git
cd irondomedev.github.io/examples/node-signup
npm ci --ignore-scripts
npm test
npm run demo

Confirmed disposable results stop the mock signup. This example deliberately fails open on screening outages, quota exhaustion, and unusable responses: the existing auth flow continues without a classification. Disposable addresses may pass unchecked during failures.

Retain your existing validation, request limits, abuse controls, and ownership verification. Enforce screening at the actual user-creation boundary; a browser pre-check is bypassable. This is not a production authentication system.
